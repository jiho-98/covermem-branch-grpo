# 구현된 방법과 비교 조건

이 코드는 첨부된 2단계 분기 GRPO 제안을 실제 RAW-turn executor와 연결한 세 번째 실험이다. 기존 A/B 선택기 학습과 다른 저장소/모듈/출력 경로를 사용한다. 이 문서의 구현 규칙을 실제 실험 조건으로 기록한다. 첨부 원문에 실린 오라클/시뮬 수치는 본 구현의 검증 결과가 아니다.

## 1. 학습 대상과 전환

Qwen3-4B-Instruct-2507 베이스는 동결한다. SFT에서 시작하는 `manager` LoRA 하나만 학습하며, SFT의 별도 동결 복사본 `manager_ref`는 KL 계산에만 사용한다. optimizer는 하나다. reference는 선택기나 학습하는 두 번째 매니저가 아니다.

대화마다 빈 뱅크 네 개와 1단계 상태에서 시작한다. 각 세션을 네 경로 모두 같은 정책 버전으로 수집한다. 세션 종료 시점의 content 문자 사용량이 **네 뱅크 모두 43,500 × 0.95 이상**이면 다음 세션부터 2단계로 바꾼다. 과거에 각각 한 번 찼다는 것만으로는 전환하지 않으며, 같은 세션 끝에서 동시에 조건을 만족해야 한다.

전환을 결정한 세션은 끝까지 1단계다. 이미 2단계이면 공간이 생겨도 돌아가지 않는다. 대화가 바뀌면 뱅크/phase를 새로 시작하되 학습된 매니저 파라미터는 이어간다. phase, 전환 세션, 경로별 처음 95%에 도달한 턴/세션을 checkpoint에 저장한다.

## 2. 1단계: 기존 LOO의 정확한 의미

프롬프트, RAW executor, 5개 액션, 학습 시 최대 3시도, 세션 중간/끝의 누적 QG 질문, action-aligned LOO continuation gain을 보존한다. 원래 누적 질문에는 중복 제거를 추가하지 않는다.

첨부 원문의 중간/끝 advantage 표기는 개념 설명이다. 실제 원본은 각 출력 직전 뱅크 점수를 빼는 continuation gain을 구하고, **같은 원문 턴에서 자기 경로를 제외한 세 경로의 첫 시도**를 기준값으로 쓴다. 세션 전체에 하나의 경로 advantage를 복사하는 구현으로 바꾸지 않았다. 중간/끝 가중치 0.5/0.5, 고정 scale `0.008103060640792133`, invalid ceiling −0.5를 유지한다.

첨부안 5장의 요구에 따라 분기 실험과 matched 기준선은 이 원래 계수 계산 **이후** 세션 출력들의 표준편차로 추가 나눈다. 따라서 “기존 1단계 그대로”는 원래 생성/credit 계산을 뜻하며, 최종 loss 계수의 크기까지 동일하다는 주장은 하지 않는다. 추가 정규화를 넣지 않은 `vanilla_original`도 함께 제공한다.

## 3. 2단계: 전체 행동 출력의 local 비교

각 경로 g, 턴 t에서 독립 Bernoulli(p)를 뽑는다. 기본 K=4,p=0.25다. 추첨은 reward나 행동을 보기 전에 결정하며 seed/대화/세션/경로/턴/정책 버전으로 재현 가능하다. 재개해도 같은 추첨과 샘플 seed를 쓴다.

- 분기 상태: 같은 입력 뱅크·현재 턴으로 매니저 전체 응답을 K회 생성한다. 중복 행동/대상을 그대로 둔다.
- 비분기 상태: 한 응답만 생성하고 실행한다. policy loss와 KL loss 양쪽 모두에 넣지 않으며 기존 LOO도 붙이지 않는다.
- 분기 상태의 실제 진행: 코드 index 0인 **샘플 1**만 실행한다. 점수/advantage/validity 순위로 선택하지 않는다.
- 샘플 1이 무효이면 뱅크를 그대로 둔다. 다른 K개에서 유효/최고 후보를 골라 실행하지 않고 추가 재시도도 하지 않는다. 원래 텍스트·토큰·logprob를 그대로 보존한다.

분기 모드의 매니저 프롬프트에 ADD/SKIP/REPLACE만 사용할 수 있다는 지시를 추가하고 executor에서도 강제한다. 모델 입력에 질문/정답/근거 라벨/CPU 점수/최선 후보는 없다. 선택 가능한 대상 전체가 뱅크에 보이며, 모델이 실제로 고른 K개만 가상 실행·채점한다. 전체 가능한 대상의 점수를 미리 구하지 않는다.

**사용자 확인 사항:** 1단계 UPDATE로 여러 원문 턴이 한 항목에 묶였으면 이를 유지한다. 대상은 `memory_id`이며 REPLACE는 그 항목의 source turn 전부를 제거한다. 2단계에서 UPDATE/DELETE를 출력하면 무효다. 뱅크 항목을 원문 턴별로 다시 분해하지 않는다.

## 4. 질문 풀과 보상

2단계는 해당 훈련 대화에서 생성된 **전체 QG 질문**을 사용한다. 미래 세션에서 생성된 질문도 포함하고, 충분 근거 식이 동일한 질문을 한 개로 합친다. 충분 근거 식은 “여러 대안 중 하나(OR), 그 대안 안의 모든 턴(AND)” 구조다. OR 대안/AND 턴의 순서를 정규화해 비교하며, 근거 ID의 단순 합집합이 같은 것만으로 합치지 않는다. 서로 다른 대화는 섞지 않는다.

| 대화 | 원래 전체 생성 질문 | 2단계 중복 제거 후 |
|---|---:|---:|
| conv-43 | 675 | 496 |
| conv-44 | 658 | 497 |
| conv-48 | 703 | 509 |
| conv-49 | 590 | 411 |
| conv-50 | 712 | 500 |
| 합계 | 3,338 | 2,413 |

각 distinct evidence 식에 같은 비중을 준다. 합쳐진 질문 ID 목록을 보존한다. 공식 평가 질문은 훈련 reward에 쓰지 않는다.

```text
U(M,Q) = mean_q [0.7 × 충분 근거 확보 여부 + 0.3 × 최대 근거 재현율]
r_k = U(M ⊕ a_k, Q전체·중복제거) − U(M, Q전체·중복제거)
b_(g,t) = mean_k(r_k)
A_raw_(g,t,k) = r_k − b_(g,t)
```

SKIP의 유효 reward는 0이다. 공간이 있는 ADD와 유효한 REPLACE는 기존 executor로 가상 뱅크를 만들어 채점한다. ADD/REPLACE가 43,500자를 넘거나 대상/JSON/source IDs/출력 길이가 무효이면 **−2**를 준다. 유효 점수 차이는 [−1,1]이므로 −2는 항상 더 낮다. raw text를 잘라 넣거나 자동으로 다른 항목을 더 제거하지 않는다.

invalid도 K개 평균과 advantage에 포함한다. 전부 invalid 또는 모두 동점이면 local advantage는 모두 0이다. invalid가 섞이면 유효 출력이 실제 delta가 음수여도 invalid보다 나아 양의 local advantage를 받을 수 있으며, 이는 상대 비교의 결과다.

획득/손실 충분 근거 문항 수와 부분 근거의 점수 증가/감소도 기록한다. 중복 제거 후 문항 수이며 실제 QA 정답 수는 아니다. `utility_gain − utility_loss = reward`다. 미래 턴을 이어 생성해서 분기하지 않고, 후보 행동 직후의 뱅크를 전체 질문 풀로 채점한다.

## 5. 세션 단위 정규화와 loss

원래 4경로 LOO baseline과 2단계 K샘플 baseline을 혼합하지 않는다. 2단계에서 raw advantage는 각 (g,t)의 K개 안에서만 계산한다. 세션 내 다른 상태/경로를 사용해 baseline을 다시 계산하지 않는다.

한 세션의 **학습에 포함되는 출력 하나당 advantage 하나**로 모집단 표준편차를 구한다. 토큰 길이 가중 표준편차가 아니다. 평균은 다시 빼지 않고 같은 양의 표준편차로 모두 나눈다. 1단계는 유효/무효 재시도 출력, 2단계는 선택된 분기의 K개 출력이 대상이다. 비분기 출력은 제외한다. 표준편차 ≤1e−8이면 1로 나누며, 0으로 나누거나 거대한 epsilon 역수를 만들지 않는다.

그 계수를 각 출력 전체 토큰의 PPO clipped loss에 붙이고 고정 SFT reference에 대한 기존 low-variance KL estimator ×0.02를 더한다. clip ratio=0.2, lr=5e−6, AdamW, BF16, gradient checkpointing, logits chunk=128이다. 같은 세션의 모든 학습 응답 토큰 수로 나누고 gradient를 누적한 뒤 optimizer.step을 최대 한 번 한다. 별도 target ID 마스크나 선택기 loss는 없다.

빈 학습 세션(무작위 분기 0개)이나 모든 advantage가 0인 세션은 optimizer/KL-only update를 건너뛰고 뱅크/cursor는 진행한다. 다른 비동점 상태가 있는 세션의 동점 출력은 policy gradient가 0이고 KL 항은 남을 수 있다. 수집 도중 업데이트하지 않는다.

## 6. 비교 기준선과 비용 해석

| 조건 | phase2 액션/실행 | reward | 추가 세션 std |
|---|---|---|---|
| branch | 3액션, p확률 K회·샘플1, 무효 no-op | 분기 상태의 전체 QG 순이익 | 사용 |
| vanilla_matched | 같은 전환/3액션, 턴당 1회, 무효 no-op | 중간/끝 누적 QG의 기존 LOO | 사용 |
| vanilla_original | 전 구간 5액션·기존 재시도 | 중간/끝 누적 QG의 기존 LOO | 없음 |

matched 기준선은 액션 제한/정규화 차이를 맞춰 분기 실험과 비교하기 위한 조건이다. 분기 여부, 학습 대상 선택, reward pool/credit이 바뀌는 효과를 묶어서 비교하므로 한 요소만의 완전한 causal ablation이라고 주장하지 않는다. original 기준선은 새로운 제안이 기존 방식 전체보다 나은지를 확인하는 별도 기준이다. 기존 A/B 저장소의 결과 폴더나 역사적 vLLM 수치를 그대로 대체하지 않는다.

phase2의 경로·턴당 기대 생성 수는 `1+(K−1)p`, 기대 학습 출력 수는 `Kp`다. K4,p0.25면 각각 1.75와 1이다. 이는 응답 길이, 분기 동점, 오류, 문맥 길이, optimizer skip, 원래 재시도에 따른 비용을 고려한 시간/FLOPs 동등성 증명이 아니다.

이 이식판은 HF/PEFT의 순차 생성이며 K개 간 prefix cache를 공유하지 않는다. 첨부안의 vLLM prefix caching 속도 예상은 이 실행기에 적용되지 않는다. 실제 `collection_seconds`, `update_seconds`, 생성/학습 토큰 수, peak GPU 메모리를 기록해 비교한다. p0.5/p1 config는 제공하지만 자동으로 실행하지 않는다.

## 7. 평가와 모니터링

평가는 완료 checkpoint로 held-out 대화마다 빈 뱅크 하나를 greedy 실행한다. K분기/CPU oracle/학습은 없다. branch와 matched는 **자기 평가 뱅크가 세션 끝에 95% 이상이면 다음 세션부터 같은 3액션 규칙**을 사용한다. 평가에는 네 훈련 경로가 없으므로 all-four 게이트를 평가에 복제하지 않는다. original은 전 구간 기존 5액션이다. 1단계 평가 재시도는 원래처럼 최대6회, 2단계는1회/무효 no-op이다. 이는 train의1단계최대3회와 구분한다.

공식 질문 라벨은 한 대화의 모든 메모리 결정 후에만 읽는다. 최종 근거 커버리지/재현율/적중률(5대화/729문항)과, 기록된 실제 REPLACE 전후 근거 ID로 충분 근거 상실/확보 event를 CPU 집계한다. 같은 문항의 상실이 반복되면 event도 반복 집계된다. 마지막 점수 차이와 단순 event합이 동일하다는 뜻은 아니다. QA reader/EM/F1은 없다.

학습에서는 pre-action 사용량95% 미만의 실제 선택을 근거/비근거 턴으로 나눠 ADD 수/분모/비율을 기록한다. 근거 여부는 해당 훈련 대화 QG에 인용된 source turn의 합집합이다. 미래 QG 라벨을 모니터링에 사용하지만 행동 입력으로 제공하지 않는다. 무효로 인해 저장하지 못한 턴도 분모에 포함한다. 이미2단계인데95%미만으로 내려간 상태도 이 사용량 기준 집계에 들어간다.

학습의 `scored_executed_replace_lost_complete`는 무작위 선택된 분기에서 실제 실행된 REPLACE만의 수치다. 비분기 턴까지 채점한 전체 손실로 읽지 않는다. 평가의 post-hoc event는 모든 실제 REPLACE를 포함한다. ADD율 비교는 방문 상태가 다른 관측 통계이며 자동으로 causal 효과라고 해석하지 않는다. 경보 임계값·학습률 자동 감쇠·초반 KL replay·oracle SFT 보완은 제안의 선택 사항으로 남겨 두었고 자동 적용하지 않았다.

## 8. 보존·재개

checkpoint에 manager/optimizer/RNG/각 대화4뱅크/cursor/phase latch/95%도달 이력을 함께 저장한다. 배치(=세션)가 끝난 뒤 COMMITTED marker와 원자적 rename으로 확정하고 최신 두 개를 보존한다. 모든 배치의 trace/metrics는 따로 보존한다. 미확정 세션은 재개 시 처음부터 재수집한다.

연구 조건/코드/runtime fingerprint가 바뀌면 이전 checkpoint를 이어 쓰지 않는다. supervisor는 한 GPU allocation의 owner로 남고 smoke/train/eval/analyze를 자식 단계로 실행한다. 큐를 원자적으로 다시 읽으며 실패 단계만 중단/재개할 수 있다. 정상 완료 시 자원을 반환하고, 실패 수리 대기는 기본30분으로 제한한다.
